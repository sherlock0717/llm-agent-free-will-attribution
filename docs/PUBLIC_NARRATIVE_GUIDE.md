# 公开页面叙事与语言规范

## 1. 页面承担的任务

公开页面先帮助读者理解研究问题，再提供证据和技术入口。页面需要让首次访问者在较短时间内回答四个问题：

1. 这个项目研究什么；
2. 研究A与研究B有什么关系；
3. 目前已经得到哪些结果；
4. 哪些内容属于研究计划、方法或复现材料。

项目的统一主线是：当一个AI或人类作出决定时，语言模型会不会根据行动者身份和决策过程的描述，改变对其能动性、心智状态、选择自主性与责任的评价。

研究A用于观察这种变化是否出现。研究B进一步拆分备选方案、理由、反馈以及反馈后的维持或改变，分析哪些线索推动了评价变化。

## 2. 公共名称使用研究功能，不使用修改记录

公开页面、README和面向读者的仓库文档使用研究问题和分析内容命名。以下名称不进入公开标题、章节名、按钮、结果摘要和页面说明：

- V1、V2、R1、R2；
- 新版、旧版、历史版、当前版；
- 本轮改版、修改后、重构后；
- legacy、compatibility、migration；
- 用提交、PR或文件演化过程解释研究内容的表述。

场景级分析统一称为“不同场景中的结果一致性”或“场景级分析”。原有推断统计统一放在“补充统计与技术结果”中。文件名和代码标识也应逐步改为研究功能名称，例如 `scenario_analysis`、`scenario_summary`，避免把开发阶段写进长期资产名称。

## 3. 先讲具体情境，再引入术语

每个页面先给出一个实际材料例子。例子应说明同一行动可以被写成不同的决策过程：

- 只写最终决定；
- 展示备选方案；
- 给出理由；
- 收到反馈；
- 反馈后维持或改变决定。

读者先理解材料发生了什么，再接触“行动者归因”“评价维度”“预设比较”等术语。术语首次出现时用一句自然语言解释，不把缩写作为标题主体。

## 4. 叙事顺序

公开页面采用以下顺序：

1. 研究问题；
2. 一个具体例子；
3. 研究做法；
4. 主要发现或当前进度；
5. 结果含义；
6. 方法、数据与复现。

结果页面先给出读者需要带走的结论，再提供表格、统计量和文件入口。方法页面可以保留完整技术细节，默认可见层级应低于研究问题和结果解释。

## 5. 研究A与研究B的关系

全站使用同一关系说明：

- 研究A观察身份标签和过程描述是否会改变模型评价；
- 研究B固定机器主体，把过程描述拆成更具体的决定信息、反馈和后续行为；
- 两项研究共同回答模型如何根据材料线索评价一个作出决定的主体。

避免把两项研究写成相互独立的资产清单，也避免用“广义基线”“测量深化”等抽象标签替代具体研究关系。

## 6. 结果表达

每项主要发现都应回答四件事：

- 比较了什么；
- 观察到什么；
- 这个变化怎样理解；
- 证据覆盖到哪里。

图表说明同时写明“图中比较什么”“应该看哪里”“结果说明什么”。不能只陈列横轴、纵轴、均值差和统计字段。

研究A已有数据，可以使用“发现”“观察到”“结果显示”等表述，并同时标明模型配置、材料和Prompt范围。

研究B在正式双模型运行前使用“研究设计”“材料与分析计划”“分析界面示例”等表述。示例数值不写成研究发现。

## 7. 避免AI式陈列和元话语

正文以完整段落推进论证。列表只用于条件、步骤或并列项目，不把连续解释拆成大量同构卡片和短句。

避免以下写法：

- “本节将展示……”；
- “下面从三个方面……”；
- “首先、其次、最后”机械串联；
- 连续出现结构完全相同的卡片；
- 每段都用结论句复述标题；
- 用“值得注意的是”“需要指出的是”等空泛引导；
- 用大量状态标签、徽章和数字替代解释。

优先写清楚具体主体、动作、比较和结果。句子长度与结构可以变化，段落之间通过问题推进，而非通过模板词连接。

## 8. 避免对举式和防御式表达

减少“不是……而是……”“并非……而是……”“不等于……”“不能……”“无法……”等对举或防御句式。存在边界时直接写适用范围和下一步。

示例：

- 使用“结果描述该模型配置在这批材料中的评价模式”；
- 使用“正式双模型运行完成后，页面将更新研究B结果”；
- 使用“场景级分析用于观察结果在八类任务中的一致程度”；
- 使用“技术统计保留在补充区域，主页面集中解释主要结果”。

## 9. 信息层级

首层直接显示：

- 研究问题；
- 具体材料例子；
- 研究A主要发现；
- 研究B当前进度；
- A与B的关系。

第二层显示：

- 实验设计；
- 场景与条件；
- 评价维度；
- 数据范围；
- 场景一致性。

第三层默认折叠或链接到仓库：

- 完整公式；
- p值、效应量、收敛信息；
- 内部一致性系数；
- 模型精确ID；
- JSON、哈希、发布检查；
- 运行命令和目录结构。

## 10. 页面检查标准

发布前使用四种阅读视角检查：

1. 没有研究背景的首次访问者；
2. 心理学或社会科学学生；
3. AI产品、评测或数据从业者；
4. 关注方法与复现的技术读者。

每种视角都应能够说明：

- 项目研究什么；
- 研究A和研究B怎样衔接；
- 研究A已经发现什么；
- 研究B目前完成到哪里；
- 页面中的示例数据与研究结果如何区分。

任何一种视角无法完成以上任务时，继续调整叙事和信息层级，不通过增加更多说明文字解决。
