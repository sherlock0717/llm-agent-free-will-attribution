# 评测与产品检查清单

本清单把项目中的研究问题转化为可选的工程检查项。它不限定用途，也不把任何一项当作通用标准；实际使用时需要根据任务、用户、风险和权限调整。

## 一、先明确测量对象

- [ ] 最终任务结果、可观察过程和主体归因是否分别记录？
- [ ] “解释得像推理”是否与真实工具调用和执行轨迹交叉验证？
- [ ] 量尺、分析单位和独立样本含义是否写清楚？
- [ ] 总体均值是否同时报告场景范围和失败类型？

## 二、材料与Rubric

- [ ] 身份、过程、结果和任务难度是否分开控制？
- [ ] 备选、理由、反馈和后续行动是否能单独核查？
- [ ] 新增文字是否提供真实信息，而不是只增加长度和流畅度？
- [ ] 方向版本是否在后果、合理性和语言强度上可比？
- [ ] 结构错误与语义不确定项是否分开处理？
- [ ] 是否覆盖多个场景、方向和风险等级？

## 三、Agent轨迹

- [ ] 是否识别备选方案、目标和硬约束？
- [ ] 工具选择、参数和调用顺序是否正确？
- [ ] 是否识别反馈中的有效信息？
- [ ] 是否更新计划，且更新真正进入后续执行？
- [ ] 是否记录恢复步数、重复操作、副作用和不可逆变化？
- [ ] 是否提供停止、回退或人工接管路径？
- [ ] 解释文本与轨迹和最终状态是否一致？

## 四、产品交互

- [ ] 产品把系统定义为信息源、建议者、审批者还是执行者？
- [ ] 身份名称、头像、第一人称和解释详细度是否改变用户授权？
- [ ] 用户接受、复核、覆盖、中止和回退行为是否被记录？
- [ ] 信任程度是否与真实准确率和不确定性匹配？
- [ ] 失败后，用户是否知道由谁处理、如何申诉和恢复？
- [ ] 功劳、过错和责任是否因拟人化表达发生不合理转移？

## 五、部署与治理

- [ ] 谁拥有最终决定权、覆盖权和中止权？
- [ ] 人工复核是否拥有足够信息、时间和权限？
- [ ] 高风险和不可逆操作是否需要更严格门禁？
- [ ] 事故、升级和回退是否有可追踪记录？
- [ ] 评价是否覆盖实际用户、文化、场景和组织流程？

## 研究依据

- 研究A：身份和完整过程写法对应不同的归因评分，且幅度随场景变化；
- 研究B：96条材料将备选、理由、反馈和后续行动拆成可比较条件；
- 相关前沿：过程监督、推理忠实性、Agent轨迹评价、人机信任与场景化风险管理。
