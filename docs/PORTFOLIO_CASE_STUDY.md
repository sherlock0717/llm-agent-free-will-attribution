# 项目案例摘要

## 30秒概览

**LLM行动者归因评测**是一套从心理学构念出发建立的研究工程系统。项目研究身份、理由、反馈和后续行动如何影响语言模型对行动者自主性、意图、自由选择和责任的判断，并把这一问题转化为材料条件、评价维度、数据契约、结构审计、统计分析和公开页面。

## 项目挑战

常见模型评测容易把三件事混在一起：

- 系统是否完成任务；
- 系统展示了怎样的过程；
- 评价者如何理解这个行动者。

当解释更完整、身份更像人或系统表现出反馈后的调整时，评价可能随之变化。项目需要在保持任务语境和评价流程一致的前提下，把这些线索拆开并记录。

## 负责内容

### 构念与研究设计

- 定义任务结果、可观察过程和主体归因三个层次；
- 设计身份标签、六种过程写法和八个任务场景；
- 将备选、理由、反馈、维持和改变转成研究B的六种材料条件；
- 映射题项、原量尺和预设比较。

### 数据与分析

- 解析并计分360次DeepSeek模型问卷评分输出；
- 按场景、身份和过程条件形成96个聚合分析单元；
- 完成条件差异、身份差异、场景范围和留一场景分析；
- 为研究B建立离线评分Schema与分析协议。

### 工程与质量保障

- 建立数据契约、严格JSON、结构审计和生成物检查；
- 保护历史输出，避免测试或重跑覆盖研究数据；
- 使用Ubuntu与Windows双平台CI；
- 统一组装项目总览、研究A、研究B和兼容路由。

## 关键产出

| 产出 | 内容 |
|---|---|
| 研究A | 360次模型评分、8个场景、6种过程条件、2种身份标签 |
| 研究B | 96条材料、4个主要评价维度、6项预设比较 |
| 工程资产 | 数据契约、离线导入格式、材料审计、跨平台CI |
| 展示资产 | 项目总览、研究A结果页、研究B设计页、复现文档 |

## 主要结果

- 在1—7分量尺上，高结构过程写法的能动性评分平均高1.263分；
- 在1—7分量尺上，人类标签下的自由意志归因平均高0.760分；
- 两类差异的方向较一致，但变化幅度随任务场景而变；
- 文本长度与过程条件共同变化，因此过程结果按两种完整写法理解。

## 实际价值

### Agent轨迹评价

研究B的反馈—维持—改变结构可以转成轨迹Rubric，检查系统是否识别反馈、更新计划并落实到执行，同时记录恢复、重复操作、副作用和回退能力。

### 产品与用户研究

身份名称、解释详细程度和自动化范围可以作为产品实验变量，观察用户的接受、复核、覆盖、中止和责任判断是否与系统真实能力匹配。

### Benchmark与数据工程

项目展示了如何从构念定义走到条件矩阵、题项映射、数据Schema、结构审计和生成物门禁。该方法适用于需要可追溯材料和稳定判分链路的评测项目。

### 场景化治理

场景差异说明总体平均分不能代替具体任务评价。部署时需要同时记录任务风险、人机角色、审批与中止权限、回退路径和责任链。

## 关键工程判断

1. **各构念保留原始量尺并分别报告。** 不同来源的评价维度保持各自含义，避免单一总分掩盖差异。
2. **解释文本与行为证据交叉检查。** 公开理由作为可观察输出，与工具调用、执行轨迹和最终状态共同判断。
3. **固定数据承担流程校验角色。** 示例用于验证导入、汇总和绘图链路，正式评价记录使用独立来源状态。
4. **历史研究输出保持只读。** CI和测试在临时目录运行，生成物门禁负责发现漂移而非覆盖已有数据。
5. **模型执行与离线分析解耦。** 外部评分只需遵守Schema即可进入同一分析流程，仓库默认不触发真实API。
6. **结构问题与语义问题分层记录。** 网格、字段、重复和长度阈值由确定性审计处理，语义判断保留独立状态。
