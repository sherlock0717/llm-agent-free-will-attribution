# 公开页面表达规范

本规范适用于项目总览、研究A、研究B、README和公开数据说明。

## 1. 零基础读者优先

首次出现“行动者归因”时，用自然语言解释为：模型如何判断行动者是否自主、有意图、能影响结果或应承担责任。

数字同时说明量尺和分析单位：

- 360表示模型评分输出次数；
- 16和48表示材料组合的配对数量；
- 1.263和0.760位于1—7分量尺；
- 场景单元不写成人类被试或独立实验。

## 2. 总览页

顺序保持：研究问题、研究A/B入口、主要发现、两项研究、实践与前沿价值、数据与复现。总览页不使用“支持什么／不支持什么”式章节，也不反复解释页面职责。

## 3. 研究A

首层固定呈现：

1. 高结构过程写法与能动性评分；
2. 人类标签与自由意志归因；
3. 方向一致性和场景幅度。

过程结果按两种完整写法解释，身份结果首层聚焦自由意志归因。文本长度和历史探索模型放在稳健性与方法部分。

## 4. 研究B

首层呈现六种材料、四个主要维度和六项比较。材料浏览器只出现一次，所有HTML id保持唯一。固定分析示例默认折叠，并明确写成分析流程示例。

## 5. 实践与前沿价值

论述必须从研究发现出发，并建立清楚的对应关系：

- 过程监督：结果与中间步骤为何需要分开；
- 推理忠实性：解释文本为何要与行为证据交叉验证；
- Agent轨迹：反馈、计划、执行、恢复和副作用如何评价；
- 产品交互：身份与拟人化如何影响信任、授权和责任；
- 部署治理：场景、权限、可逆性和人机角色如何进入评价。

避免“赋能产品”“提升体验”“具有重要意义”等无具体变量的概括。每一部分至少写出可观察对象、可操作指标和适用边界。

## 6. 工程与测试

测试锁定页面结构、路由、数据来源、高风险误述和HTML唯一性，不锁定普通同义词。正常加载时隐藏技术状态提示，错误时保留可恢复信息。

## 7. 发布检查

1. 首屏可直接进入研究A和研究B；
2. 两个详细页均可返回总览；
3. 研究B不存在重复id；
4. 研究A样本结构和量尺可被零基础读者理解；
5. 固定示例不会被误读为正式结果；
6. 旧探索报告不会覆盖当前稳健性解释；
7. JSON、路由、资源和生成物检查通过。

## 作品集包装

1. 总览页先回答项目是什么、完成了什么、产生了什么结果，再进入方法与限制。
2. 不使用“证据支持什么／不支持什么”“当前结果来自……”等防御式章节标题。
3. 不把实践意义写成用途清单。采用“研究线索 → 现实工程问题 → 可观察指标”的结构。
4. 研究A保持结果页角色；研究B保持评测设计页角色，不用固定示例制造正式结果感。
5. 个人能力通过构念设计、材料与题项、数据契约、分析、审计、CI和公开交付来体现，不使用空泛的“全链路”“赋能”“闭环”等表述。
6. 首屏数字必须说明计数单位。360是模型评分输出次数，96是结构化材料数量，1005是自动化测试数量。
7. 前沿研究用于解释工程问题的来源和评价方法，不把外部论文写成本项目已经完成的验证。
