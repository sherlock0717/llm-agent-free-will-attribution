# 公开页面表达规范

本规范适用于项目根页面、研究A页面、研究B页面、README，以及由生成脚本写入公开页面的数据说明。

## 1. 基本结构

每项研究按以下顺序介绍：

1. **研究对象**：记录哪一种模型归因反应；
2. **研究设计**：操纵哪些线索，使用哪些构念和材料；
3. **已有成果**：已经形成的材料、数据、分析和复现资产；
4. **扩展路线**：下一阶段增加的模型、场景、测量或分析证据。

公开页面优先说明研究内容和证据用途。方法边界集中放在“证据组成”或“研究状态”区域，用一到两段完成说明。

## 2. 数据类型统一口径

| 数据资产 | 公开名称 | 说明 |
|---|---|---|
| 研究A既有记录 | DeepSeek API 模型模拟问卷响应 | 单一模型配置按问卷模拟 Prompt 生成的 360 条记录，用于描述该配置在研究A材料中的归因反应。 |
| 研究A mock | 确定性工程验证数据 | 用于检查运行器、解析、计分和产物契约。 |
| 研究B demo | 流程演示数据 | 用于呈现材料、评分、分析和图表链。 |
| 研究B正式运行 | 双评判模型运行数据 | 两个评判模型对同一套机器主体材料进行评分。 |

`synthetic` 仅作为兼容字段。新数据契约优先使用：

- `respondent_mode`
- `generation_source`
- `data_role`

## 3. 正向表达方式

公开页面采用“当前用途 + 扩展路线”的写法。

推荐：

- “当前结果描述该模型配置在本材料集中的归因反应。”
- “下一阶段将加入跨模型运行、Prompt 改写和场景级稳健性分析。”
- “测量验证路线包括题项结构、构念区分和跨主体可比性。”
- “仓库提供工程流程、聚合分析和公开产物的复现；新运行将完整保存逐请求记录。”
- “两项研究分别保存材料、题项、数据和分析结果。”
- “该路径分析用于描述变量之间的关联结构。”

需要改写的高频防御式句型包括：

- 仍待、尚未、未完成；
- 不能、无法、不支持、不代表；
- 不是、不得、不等于；
- 连续多句以否定方式界定研究。

上述词语并非机械禁用。技术错误、逻辑定义和必要事实可以保留；公开叙事优先改写为研究用途、数据状态和下一步行动。

## 4. 统计结果表达

研究A首层页面优先展示：

- 条件均值与差异；
- 场景方向一致数；
- 场景范围；
- 固定模型配置下的响应模式；
- 分析使用的单位和控制项。

Cronbach α 的公开标题统一为“题项内部一致性”。

`structure_level` 路径分析统一称为“探索性关联路径诊断”。

研究B的六个条件被表述为六个预先指定的 D/U 组合。C1 与 C2 分别突出备选方案和明确理由，不使用严格递进叙事。

## 5. 页面职责

- 根页面：研究计划总览、研究A/B入口、证据组成、共享方法、扩展路线；
- 研究A页面：身份标签与决策过程归因基线；
- 研究B页面：机器主体决策过程归因评测；
- 内部方法文档：完整统计假设、运行风险、数据依赖和审计记录。

## 6. 发布检查

公开发布前检查：

1. 页面名称和路由一致；
2. 数据类型使用本规范中的统一名称；
3. JSON 为浏览器可解析的标准 JSON；
4. 数字来自生成数据，不在 HTML 中重复硬编码；
5. 静态研究内容在动态数据加载异常时仍可阅读；
6. 本地预览统一从 `_site` 目录运行；
7. 根页面、研究A、研究B和兼容跳转路径均通过资源检查。
